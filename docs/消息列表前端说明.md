# 消息列表前端说明

## 1. 页面定位

消息列表是商户资金看板的统一消息中心，用于承接首页右上角消息入口里的所有提醒。

入口位置：

- 首页右上角消息铃铛图标
- 当存在未读消息时，铃铛右上角显示红点
- 点击铃铛进入消息列表页

页面路由建议：

- 消息列表：`#/messages`
- 业务详情页：`#/detail/{业务类型}/{记录ID}`

## 2. 消息类型

消息列表需要支持 5 类消息：

| 类型 | 前端标识 | 列表标签 | 用途 | 点击后行为 |
| --- | --- | --- | --- | --- |
| 销售消息 | `sales` | 销售 | 新销售订单、销售订单状态变化 | 跳转销售详情 |
| 充值消息 | `recharge` | 充值 | 充值到账、充值失败 | 跳转充值详情 |
| 提现消息 | `withdraw` | 提现 | 提现中、提现成功、提现失败 | 跳转提现详情 |
| 保证金消息 | `deposit` | 保证金 | 保证金交易状态变化 | 跳转保证金详情 |
| 审批消息 | `approval` | 审批 | 提醒商户有待审批事项 | 不跳 H5 详情，提示去 PC 端处理 |

## 3. 列表展示字段

每条消息卡片展示以下内容：

- 消息类型标签：如“销售 / 充值 / 提现 / 保证金 / 审批”
- 消息标题：如“新销售订单”“充值到账提醒”
- 消息内容摘要：一行文案，超出可省略
- 消息时间：格式建议 `YYYY-MM-DD HH:mm`
- 左侧消息图标：不同类型使用不同底色
- 右侧箭头：表示可点击

示例：

```json
{
  "id": "msg-sales-new",
  "kind": "sales",
  "title": "新销售订单",
  "content": "刚产生 1 笔新订单，点击查看订单详情。",
  "time": "2026-07-17 09:30",
  "unread": true,
  "target": {
    "type": "sales",
    "id": "sales-001"
  }
}
```

审批消息示例：

```json
{
  "id": "msg-approval",
  "kind": "approval",
  "title": "审批提醒",
  "content": "有 1 笔销售订单待审批，当前只能在 PC 端完成处理。",
  "time": "2026-07-17 09:30",
  "unread": true,
  "pcOnly": true
}
```

## 4. 跳转规则

普通业务消息点击后，按照 `target.type` 和 `target.id` 跳转到对应详情页。

| target.type | 跳转页面 |
| --- | --- |
| `sales` | 销售详情 |
| `recharge` | 充值详情 |
| `withdraw` | 提现详情 |
| `deposit` | 保证金详情 |

跳转路径：

```text
#/detail/{target.type}/{target.id}
```

例如：

```text
#/detail/sales/sales-001
#/detail/recharge/recharge-001
#/detail/withdraw/withdraw-006
#/detail/deposit/deposit-005
```

审批消息不跳转 H5 详情页。点击后只提示：

```text
请到PC端完成审批操作
```

## 5. 未读红点逻辑

首页右上角消息铃铛的红点用于提示“有未读消息”。

建议逻辑：

1. 后端返回消息列表时，每条消息带 `unread` 字段。
2. 只要存在 `unread = true` 的消息，首页铃铛显示红点。
3. 用户进入消息列表页后，可视为已读，调用“标记已读”接口。
4. 标记成功后，回到首页时红点消失。

前端状态判断：

```ts
hasUnread = messages.some(item => item.unread)
```

## 6. 接口建议

### 6.1 获取消息列表

```http
GET /api/merchant/messages
```

返回字段建议：

```ts
interface MerchantMessage {
  id: string
  kind: 'recharge' | 'withdraw' | 'deposit' | 'sales' | 'approval'
  title: string
  content: string
  time: string
  unread: boolean
  target?: {
    type: 'recharge' | 'withdraw' | 'deposit' | 'sales'
    id: string
  }
  pcOnly?: boolean
}
```

### 6.2 标记消息已读

```http
POST /api/merchant/messages/read
```

可选参数：

- 不传消息 ID：标记全部已读
- 传消息 ID：标记单条已读

## 7. 交互注意事项

- 消息列表页不展示底部导航，避免和返回逻辑冲突。
- 页面左上角返回按钮使用浏览器历史返回。
- 如果用户从首页进入消息列表，返回后应回到首页。
- 如果消息目标记录不存在，建议提示“记录不存在或已更新”，不要白屏。
- 审批类消息当前只做提示，不在 H5 内处理审批。
