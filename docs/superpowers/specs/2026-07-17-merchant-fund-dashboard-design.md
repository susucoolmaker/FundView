# 商户资金看板设计规格

日期：2026-07-17  
状态：已完成会话设计确认，待书面规格复核

## 1. 产品目标

“商户资金看板”是嵌入企业微信工作台的移动端 H5，供加盟商查询商户级钱包余额、门店资金记录、保证金余额和销售明细。首版使用本地 Mock 数据，交付为可直接执行 `npm install`、`npm run dev` 的高保真 Vue 3 Demo。

产品不包含登录页、不接入真实后端，也不模拟企业微信原生导航栏或手机系统状态栏。页面内部只绘制业务标题、详情返回栏和底部一级导航，避免嵌入企业微信后形成双重导航。

## 2. 已确认的核心资金口径

### 2.1 钱包余额

- 钱包余额是商户级共享资金池，Mock 金额为 `568420.36`。
- 三家门店共同使用该余额。
- 门店切换不会改变钱包余额。
- 首页主卡固定显示“钱包余额”、格式化金额和辅助文案“全部门店共用余额”。
- 商户名称“华北恒信通讯有限公司”以小字显示在钱包余额主卡中。

### 2.2 本月充值

- 统计当前自然月内当前所选门店的累计充值金额。
- 选择“全部门店”时汇总三家门店。

### 2.3 本月提现

- 只统计当前自然月内状态为“提现成功”的金额。
- 选择“全部门店”时汇总三家门店。
- 首页明确显示“仅统计提现成功金额”。

### 2.4 当前保证金余额

- 使用门店数据中的 `currentDepositBalance`，不从历史记录反推。
- 北京望京店为 80000，北京中关村店为 70000，北京国贸店为 50000。
- “全部门店”为三家门店之和 200000。
- 该余额是当前时点余额，不受本月周期限制。

## 3. 视觉方向

- 设计基准宽度 750px，对应常见 375px 手机视口。
- 页面背景为浅灰白，卡片为白色，核心品牌色固定为 `#6E20AF`。
- 不使用紫蓝渐变、大面积科技蓝、发光或玻璃拟态。
- 企业后台风格稳重、清晰，使用适度圆角、弱阴影和浅紫色强调区。
- 成功、处理中、失败和中性状态分别使用绿色、橙色、红色和灰色，并始终附带状态文字。
- 页面文字和触控区按需求给出的 750px 尺寸规范实现，不以压缩字号换取一屏信息量。
- 自定义样式使用 750px 设计稿尺寸编写，通过 `postcss-px-to-viewport` 转换；排除 `node_modules` 中的 Vant 样式。
- 页面根容器禁止横向溢出，底部固定导航和详情内容均适配 `env(safe-area-inset-bottom)`。

## 4. 页面与导航结构

一级导航包括首页、明细、我的：

- `/dashboard`
- `/records/recharge`
- `/records/withdraw`
- `/records/deposit`
- `/records/sales`
- `/profile`

详情路由包括：

- `/detail/recharge/:id`
- `/detail/withdraw/:id`
- `/detail/deposit/:id`
- `/detail/sales/:id`

根路径重定向到 `/dashboard`。一级页面显示固定底部导航，详情页通过路由元信息隐藏底部导航并显示业务返回栏。

## 5. 首页设计

### 5.1 顶部信息区

顶部显示页面标题“资金看板”和当前门店。点击门店进入 Vant 底部 Popup + Picker。商户只有一家门店时仍显示门店名称，但弱化切换箭头。

### 5.2 钱包余额主卡

钱包余额是首页第一视觉焦点：

- 卡片顶部小字展示商户名称。
- 中部展示标题“钱包余额”和大金额 `¥568,420.36`。
- 辅助文字为“全部门店共用余额”。
- 卡片不包含门店切换入口。
- 卡片保持白底，可用浅紫底块强化金额，但不使用深紫整卡或渐变。

### 5.3 门店联动资金概览

钱包卡下方展示本月充值、本月提现、当前保证金余额。三项随顶部门店选择联动；钱包余额始终不变。当前保证金余额的视觉权重高于月度发生额，但低于钱包余额。

### 5.4 常用功能与最近记录

四个入口分别进入充值、提现、保证金和销售明细，并继承当前选择的门店。最近记录混合展示四种业务的最新五条记录；门店切换后重新筛选，点击整卡进入相应详情。

## 6. 明细查询与列表

明细页顶部为可吸顶的四业务标签。标签切换通过路由完成，保留品牌色选中态。

查询区采用两行紧凑布局：

1. 日期和门店筛选。
2. 搜索输入框、查询按钮及弱化的重置入口。

日期支持今天、本月、上月和自定义范围，默认本月。自定义范围使用 Vant Calendar。充值、提现和保证金支持流水号部分匹配及金额精确匹配；纯数字输入同时尝试流水号和金额。销售支持销售单号部分匹配和商品名称模糊匹配。

查询使用“草稿条件”和“已应用条件”两层状态：修改筛选项不会立即刷新，点击查询后才应用；重置恢复本月、全部门店和空搜索并立即刷新结果。列表上方显示已应用条件摘要和结果数量。

列表统一使用 Vant PullRefresh 和 List：

- 每页 20 条。
- 支持下拉刷新、上拉加载、加载中和没有更多。
- 区分完全无业务数据、查询无结果、网络异常、登录失效和无权限。
- 点击整张记录卡进入详情。
- 从详情返回时恢复业务标签、日期、门店、搜索词、分页数据和滚动位置。

## 7. 业务记录与详情

充值、提现、保证金和销售使用共享列表壳层，但由业务配置对象定义标题、搜索提示、金额方向、主字段和详情字段，避免单组件内堆积条件分支。

- 充值：至少 12 条，详情含资金凭证。
- 提现：至少 10 条，覆盖六类状态；失败和驳回显示对应原因；详情含资金凭证。
- 保证金：至少 10 条，覆盖缴纳、补缴、扣除、退回和调整；详情含资金凭证。
- 销售：至少 20 条，覆盖五类结款状态；商品名最多两行；详情不显示资金凭证。

长流水号和销售单号完整换行显示，并提供复制按钮。可选字段无值时不渲染对应行。

## 8. 资金凭证

充值、提现和保证金详情使用统一 VoucherPreview：

- 展示保持比例的大矩形缩略图。
- 点击调用 Vant ImagePreview 全屏预览。
- 数据结构支持多张图片和左右切换，首版单条记录可只配置一张。
- ImagePreview 提供双指缩放。
- 图片加载失败显示异常占位；空数组显示“暂无资金凭证”。

凭证示例使用项目内本地资源，确保离线 Mock Demo 可用，不依赖临时外链。

## 9. 我的页面

页面展示商户头像占位、商户名称、管理员身份、实名编码和脱敏手机号。提示区显示账户正常及北京国贸店员工绑定异常两条消息。我的店铺纵向展示三家门店的编码、员工数和绑定状态，使用语义状态色而非紫色整卡。

## 10. 前端架构与组件边界

技术栈为 Vue 3、TypeScript、Vite、Vue Router、Pinia、Vant 4、Sass、Composition API 和 `<script setup lang="ts">`。

主要边界：

- `AppShell`：根据路由元信息控制内容安全区和底部导航。
- `merchant` Store：商户、门店、共享钱包余额和当前门店。
- `records` Store：各业务查询草稿、已应用条件、分页结果和滚动位置。
- Mock Service：统一模拟延迟、过滤、分页和可控错误。
- `RecordView`：共享明细页面流程。
- 业务配置：分别定义充值、提现、保证金和销售的展示差异。
- 详情视图：共享详情壳层和字段组件，凭证区域按业务配置启用。

需求指定的公共组件全部保留：MerchantHeader、StoreSelector、FundOverview、QuickEntry、RecentRecordList、RecordTabs、RecordFilter、RecordCard、StatusTag、EmptyState、LoadingState、VoucherPreview、StoreCard、BottomNavigation、DetailField、AmountDisplay。

## 11. 数据流

1. 应用启动时从 Mock Service 加载商户、门店和业务数据。
2. 首页读取商户级钱包余额；钱包余额不依赖当前门店。
3. 首页资金发生额、保证金余额和最近记录根据当前门店计算。
4. 从首页进入明细时，记录 Store 用当前门店初始化目标业务查询条件。
5. 查询时 Mock Service 根据已应用条件过滤，再按每页 20 条分页返回。
6. 进入详情前记录滚动位置；返回列表后等待 DOM 恢复并滚动到保存位置。
7. 从底部导航重新进入明细时保留该业务上次状态；显式点击重置才清除条件。

## 12. 错误与边界处理

- Mock Service 返回网络异常时显示重试按钮，重试保持原查询条件。
- 登录失效和无权限为独立页面状态，不与普通网络错误混用。
- 找不到详情记录时显示“记录不存在或已失效”并提供返回入口。
- 金额格式化统一处理千分位、两位小数和正负方向；数据层只保存 number。
- 日期统一保存 ISO 风格日期时间字符串，由公共工具格式化。
- 搜索输入去除首尾空格；空字符串表示不限制。
- 图片加载失败、空凭证、长文本和缺失可选字段均有明确降级表现。

## 13. 验证策略

### 自动验证

- 类型检查和生产构建通过。
- 单元测试覆盖金额格式化、日期区间、状态映射、门店汇总、钱包余额不受门店影响、搜索匹配和分页。
- 组件测试覆盖门店切换、查询/重置、业务标签路由和凭证空态。

### 浏览器验证

- 以 375px 视口逐条访问全部路由。
- 验证门店切换只联动门店级指标，钱包余额保持不变。
- 验证四类搜索、日期选择、重置、刷新、加载更多和详情返回状态恢复。
- 验证凭证预览、无凭证、失败图片、长编号复制和所有异常空态。
- 验证底部安全区、详情无底部导航、无横向滚动以及窄屏文字不溢出。
- 抽查全局样式，确认品牌操作色为 `#6E20AF`，语义色未被误用为品牌色。

## 14. 首版范围外事项

- 企业微信 JS-SDK、单点登录和真实权限鉴权。
- 真实接口、服务端分页和文件存储。
- 钱包充值、提现申请或资金操作能力；首版仅查询。
- 趋势图、导出报表、消息推送和多商户切换。
